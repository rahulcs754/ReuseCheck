Stop rewriting code you already have.

AI agents rarely search the repo before they write. ReuseCheck looks at the new functions, hooks and components in each PR and tells you when one already exists, even when the names and the line order changed.

Why

Agents duplicate quietly

A second useDebounce, a third formatDate. Each one looks fine in review, because the original lives in a file the PR did not touch.

Copy-paste tools miss rewrites

jscpd and similar tools match token runs. New names and reordered lines slip past them. ReuseCheck compares structure after renaming.

Only new code is checked

Old duplicates don't spam every PR. You see matches for what this PR adds, in one comment that updates on each push.

No AI, no server

An AST parser and plain math. Fast, free, the same answer every time, and your code never leaves CI.

How it works

  1. Parse. Every JS/TS/JSX file is parsed into an AST with Babel. Functions, arrow functions, methods, hooks and components become units.
  2. Normalize. Local names become $, strings and numbers become their type, types and comments are dropped, and () => x equals () => { return x; }. The APIs a unit uses (useState, fetch, .map, <button>) are kept.
  3. Score. 70% structure (ordered token runs plus an order-free token count) and 30% shared APIs. 80% or more is reported.
  4. Compare only what's new. In a PR, a unit is new when most of its lines were added. Each new unit is compared with every other unit in the repo.

Add it to a repo

name: ReuseCheck
on:
  pull_request:
    types: [opened, synchronize, reopened]
permissions:
  contents: read
  pull-requests: write
jobs:
  reusecheck:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: rahulcs754/reusecheck@main

Or run it locally: npx github:rahulcs754/reusecheck --base origin/main, or scan the whole repo with npx github:rahulcs754/reusecheck scan.
